# M4.UI.1 — протоколы проверки знаний

Дата: 05.11.2026. Основание: `8d154d40eb1270fa1c576ddd515b3e7681e7bd3b`.

Изменения подготовлены в отдельной локальной копии `m4-ui1`, ветка
`feature/m4-ui1-20261105`. Коммитов и push нет. Исходная ветка
`feature/post-rc2-development-20261101` и Draft PR #199 не изменялись.

## Что работает

- Новый административный пункт «Протоколы проверки знаний».
- `/admin/knowledge-protocols`: компактная таблица с номером, датой, курсом,
  числом участников, состоянием и наличием скана. Поиск по номеру, курсу и
  участнику; фильтры по курсу и состоянию.
- `/admin/knowledge-protocols/new`: единственный вход в создание из нового
  раздела. После выбора курса показана существующая форма подбора участников;
  после сохранения открывается созданный протокол.
- `/admin/knowledge-protocols/:id`: отдельная карточка с шестью этапами,
  следующим действием, объяснением блокировки подписания, серверной проверкой
  перед фиксацией и компактной таблицей участников.
- В карточке сохранены существующие редактирование, печать черновика, проверка,
  фиксация, подтверждение бумажного подписания, работа со сканом и сверка Минтруда.
- Из Госреестров доступны прямые ссылки на новый раздел и исходный протокол.
  Прежний callback для открытия внутри Госреестров сохранён отдельной кнопкой.
- `/mintrud/protocols`, старый редактор в `/admin/registries` и
  `#participant=<protocol>:<enrollment>` продолжают работать.

Состояние «Подписан» отображается только при `status=recorded` и серверном
`is_signed=true`. Заполненные поля черновика не означают проведённую комиссию.
Результаты онлайн-теста не используются. Подписание и наличие скана показаны
отдельно; синхронизация не выдаётся за утверждение или отправку в ЕИСОТ.

- `smoke_admin_registries_page.py` — **известное падение исходного HEAD**:
  `page contract missing: prepareAdminFrdoPortalArtifact`. Тот же результат
  отдельно воспроизведён в исходном репозитории без изменений. Новое ожидание

- Предупреждения: устаревшие данные Browserslist, существующий общий vendor
  chunk более 500 kB; при завершении некоторых прежних SSR-тестов Vite пишет
  предупреждение об остановке фонового сканирования. Exit code тестов и сборки — 0.

Воспроизведение браузерной проверки: после сборки установить Playwright
отдельно, передать `PLAYWRIGHT_MODULE` как file URL его `index.mjs`,
`UI_BROWSER_PATH` как путь к установленному Chromium/Chrome и запустить
`node tests/knowledge_protocols.browser.mjs` из `frontend`.
Тест использует только `127.0.0.1:4179`, блокирует внешние запросы,
перехватывает весь API и закрывает свой браузер и preview-сервер.
Скриншоты и журналы сохраняются в `UI_EVIDENCE_DIR` (по умолчанию —
соседняя папка `m4-ui1-evidence`).

## Границы и риски

1. API возвращает до 100 последних протоколов, без пагинации. Поиск и фильтр
   состояния работают внутри загруженного набора; ограничение видно на экране.
   Фильтр курса выполняет отдельный запрос, а карточка читает протокол по ID.
2. Предлагаемый этап — подсказка по сохранённым полям. Только существующий
   серверный recording-readiness и обработчик фиксации разрешают фиксацию.
3. Для названий и выбора курса используется существующий каталог курсов.
   При его недоступности список показывает идентификаторы; создание требует
   восстановления доступа к каталогу.
4. Подробный редактор и карточка участника переиспользованы. Боковая панель
   участника и полноценное разделение редактора на формы этапов отложены.
5. Мобильный экран наследует длинное меню общего AppShell над содержимым.
   Таблица участников прокручивается горизонтально. Общая мобильная навигация
   не перерабатывалась в этом этапе.
6. Локальные тесты не являются приёмкой на реальном backend. Серверные
   сценарии с PostgreSQL/MinIO и GitHub CI в этом этапе не запускались.
7. После ревью нужен отдельно подтверждённый коммит/push в согласованную
   ветку PR #199 и проверка CI. PR должен остаться Draft; merge и deploy
   требуют отдельного разрешения.

## Что не затронуто

Backend, БД, миграции, права, API client, обработчик подписания/сканов,
idempotency/locks, автосинхронизация и export guards не изменены.
Алгоритмы XML Минтруда и XLSX ФРДО остались прежними. Не выполнялись операции
с production, main, compose, контейнерами, томами, PostgreSQL, MinIO или
private documents. База RC2visual не использовалась.

Финальная проверка исходной копии: прежние ветка и HEAD, ровно четыре
исходных untracked-файла. Их SHA-256 совпали с началом работы:
`backend/app/tests/m45_http_fault_server.py`, `frontend/m46a-smoke.html`,
`frontend/smoke-server.mjs`, `frontend/tests/m46a_browser.jsx`.
